# Decisions

Provisional decisions made while implementing tickets are recorded here.

## T02 — Config, CLI, and RNG

The design doc does not specify a config schema. These defaults are provisional and easy to widen later.

- Package version is `0.1.0` until a release process exists.
- Settings live in `arden.toml` in the working directory. If that file is absent, `load_config()` returns built-in defaults. `arden.example.toml` records those defaults. An explicit path that does not exist raises `FileNotFoundError`.
- `[world].tick_rate` is simulation ticks per real-time second. Default `10.0`. It must be greater than 0. The loop may still run slower than real time when the LLM is thinking; this value is the target rate.
- `[world].seed` is an integer. Default `0`. `make_rng(settings)` is the only place that constructs the simulation `random.Random`. Callers pass that instance through the run. The process-wide `random` module is not seeded or sampled.
- `[llm].backend` is a non-empty string. Default `"mock"`. Other names are accepted so a later backend is a config change. Only the mock backend is implemented in this milestone.
- `[logging].level` is a standard-library level name (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`), matched case-insensitively and stored uppercased. Default `INFO`. This is process logging, separate from the ground-truth observer log.
- Unknown keys are rejected.
- `python -m arden run` loads config, builds the seeded RNG, and passes both into `run_simulation`. The world loop is not implemented yet, so the command prints `not implemented yet`.

## T04 — World object schema

The ticket names the fields. These choices fill in representation details the design doc leaves open.

- An id is `object_<n>` with `n` a non-negative integer (`object_0`, `object_1`, …). `ObjectFactory` starts at `object_1`. It accepts an explicit id in that form, remembers ids it has issued, and rejects a duplicate. Constructing a `WorldObject` directly does not consult the factory.
- Position is `{"x": float, "y": float}` on the 2D plane. Coordinates must be finite. There is no world bound in this schema.
- `level` is the string `ground`, `raised`, `on_top_of:object_<n>`, or `inside:object_<n>`. The schema checks that shape only. It does not check that the referenced object exists. `inside` is included because the ticket requires it and section 4.1 allows putting things inside.
- `shape` is `sphere`, `cube`, `cylinder`, `flat`, or `long`. `long` is required by the ticket and matches the composite description in section 7.2.
- Height, volume, and weight are finite and `>= 0`. Rigidity is finite and in `0..1` inclusive. Zero weight is allowed; only negatives are rejected. The design doc states the rigidity range and forbids a negative weight; the other bounds keep physical magnitudes in the same family.
- `color`, when set, is a non-empty string. No palette is enforced. Unset color is left out of `perceptible()`.
- `state` is a free JSON object and is perceptible. Hidden rules do not go there.
- Hidden behavior is `behavior`: a list of `BehaviorRule` values, so two responses can share a verb (bounce and break on strike). Each rule has a `verb` key matching `^[a-z][a-z0-9_]*$` and any other JSON-valued fields as data (`scale`, `response`, `above_force`, and so on). Verbs are not limited to the current body-verb list. There is one rule model, not a subclass per object kind.
- `perceptible()` returns the perceptible physical fields: id, position, level, shape, height, volume, weight, hollow, color (if set), and state. It omits `behavior`, `velocity`, and effect-revealing properties (`fragile`, `fixed`, `binding`, and `rigidity`). The id is included as a referent, as in the intent examples that say `object_7`. It is not turned into a label. Qualitative words such as "round" or "light" are not derived here; those belong to a later perception rendering if they are wanted. Section 2 says physical parameters are exposed and their effects are learned.
- **Effect-revealing properties hidden from perception (#34)**: `fragile`, `fixed`, `binding`, and `rigidity` describe what an object does when acted upon rather than how it looks, and are not needed for perception. All four are omitted from `perceptible()` while remaining on `WorldObject` to drive physics and verb behavior (e.g., `fixed` prevents movement when pushed, `fragile` causes breaking when struck, `rigidity` governs stacking stability, and `binding` governs whether an object can tie things together).
- Unknown keys, including `name` or `label`, are rejected so a human label cannot be stored on the object.
## T03 — LLM backend, intent schema, and mock

The hardware section says the model replies with "intent, target, parameters, a short thought". That is treated as a summary of the intent contract in section 10.3. The schema implemented here is the ticket's `Intent` model, which follows that contract and adds `confidence`.

- Body verbs are the twelve names in section 6. The table cell `grab / drop` is two verbs, `grab` and `drop`. Opaque actions such as `action_3` are not in this enum. Widening the list for those is left to a later ticket.
- `Step.target` defaults to `None` and `Step.params` defaults to `{}`. Some verbs, such as `move`, `place`, and `speak`, do not take a target. Extra fields on `Intent` and `Step` are rejected. Keys inside `params` are open, because the ticket types `params` as a dict rather than a per-verb object.
- `confidence` is required and must be from 0 to 1 inclusive. Section 10.4 weights expectation surprise by confidence. The section 10.3 table does not name the field; the ticket does.
- `make_backend(settings)` reads `settings.llm.backend`. `mock` returns `MockLLM` seeded from `settings.world.seed`. Any other name raises `ValueError`. Config may still store a future name; the factory is what rejects it until that backend exists.
- `MockLLM` uses a private `random.Random` for fixture draws. It does not consume the simulation RNG from `make_rng`. `system`, `user`, and `timeout_s` do not affect the choice, and the mock returns immediately.
- A script queue of raw strings is consumed from the front before any fixture draw. Those strings may be invalid JSON. A scripted call does not advance the seed. Fixture files are `src/arden/llm/fixtures/*.json`, sorted by filename.
- Every response is parsed as JSON and checked against the `schema` argument. The checker covers the JSON Schema subset Pydantic emits for these models (`type`, `enum`, `required`, `properties`, `additionalProperties`, `items`, `minimum`, `maximum`, `anyOf`, and local `$ref`). Invalid output raises `LLMOutputError` with the raw text on `.raw`. No schema library was added.
- `role` must be `decide`, `reflect`, or `name`. Anything else raises `ValueError` and does not consume a scripted response. Reflect and name do not have their own models yet. Callers pass whatever schema those roles should return. The canned fixtures are intents.

## T05 — World state, fixed tick loop, clock, and save/load

These choices fill in container, event, clock, and snapshot details not fixed by the design doc.

- `AgentBody` holds `position` (default `(0.0, 0.0)`), `level` (default `"ground"`), `energy` (in `0..1`, default `1.0`), `comfort` (in `0..1`, default `1.0`), and `holding` (`None` or an `object_<n>` id). Despawning a held object clears `holding`.
- `World` stores objects by id in `world.objects`, the agent body on `world.body` (aliased as `world.agent_body`), the tick counter on `world.tick`, the seeded `random.Random` on `world.rng`, and an internal `ObjectFactory` so creator spawns issue sequential `object_<n>` ids. `step()` increments `tick` by 1, advances `rng` once per tick, and emits a `tick` event.
- `EventBus` (`world.events`) delivers typed `WorldEvent` subclasses (`ObjectSpawnedEvent`, `ObjectDespawnedEvent`, `ObjectMovedEvent`, `ObjectChangedEvent`, `TickEvent`) synchronously in registration order. Subscribers can listen to all events (`world.subscribe(fn)`) or a single event type (`world.subscribe("object_spawned", fn)`).
- Creator operations `world.spawn(props, pos)`, `world.despawn(id)`, and `world.move(id, pos)` default to `source="creator"` on the emitted event. `world.update_object(id, changes)` updates properties/state and emits `object_changed` (default `source="world"`).
- `WorldClock` (`Clock`) wraps a `World` and `tick_rate`, supporting `pause()`, `resume()`, `set_speed(x)` (`x > 0`), `step_once()` (steps 1 tick even while paused), `advance(dt)` (accumulates simulated seconds without sleeping), and `run(ticks)` (runs up to `ticks` steps while unpaused, defaulting to no sleeping for synchronous tests).
- `snapshot()` serializes `tick`, `body`, `objects` (including hidden `behavior` rules), `factory` id state, and `rng.getstate()` to a deterministic JSON string (`sort_keys=True`). `restore()` works on both an existing `World` instance and on the `World` class.

## T06 — 2D physics: movement, collisions, pushing, rolling, and height levels

Section 16 (open question 6) leaves open whether to use simple property rules or a light physics engine. We choose deterministic property-driven rules on the 2D plane with discrete height levels rather than an external physics engine:

- **Property-driven rules over a physics engine**: Movement, rolling, collisions, stacking stability, water drift, and occlusion are computed directly from `WorldObject` properties (`shape`, `weight`, `height`, `volume`, `rigidity`, `fixed`, `level`) with no external physics dependency. Physics does not consume draws from `world.rng`, preserving exact tick-for-tick RNG determinism.
- **Terrain grid (`TerrainGrid`, `Tile`)**: Unbounded sparse grid of cells of size `tile_size` (default `1.0`), defaulting to `"grass"`. Supports `"grass"`, `"water"` (wet; default flow `(1.0, 0.0)` unless overridden; movable objects with `weight <= 1.0` float with `state["floating"] = True` and drift downstream each tick; all ground objects in water get `state["wet"] = True`), and `"ledge"` (`level = "raised"`, elevation `1.0`; reachable only from an adjacent raised tile or from `on_top_of:object_<n>` when the support object is adjacent and has `height >= 0.15`; blocks ground-level objects from sliding onto the ledge).
- **Velocity, impulse, and shape friction**: `WorldObject.velocity` (`Velocity(x, y)`, omitted from `perceptible()`) updates positions each tick and decays by shape-dependent retention (`sphere: 0.85`, `cylinder: 0.80`, `long: 0.65`, `cube: 0.55`, `flat: 0.50`, zeroed below `0.005`). `apply_impulse(id, direction, force)` adds velocity `(force * shape_factor * rule_scale) / (1.0 + weight)` along the normalized direction (`shape_factor`: `sphere: 1.2`, `cylinder: 1.1`, `long: 0.85`, `cube: 0.7`, `flat: 0.6`), so round objects roll farther than flat/cube shapes and heavier objects move less.
- **Circle collisions**: Each object's collision radius (`obj.radius` / `object_radius(obj)`) is derived from `shape`, `height`, and `volume` (clamped to `[0.05, 2.0]`, or overridden by `state["radius"]`). Fast movement is substepped, momentum is exchanged on impact (`fixed` objects never move), and iterative positional projection with a fallback de-wedging pass guarantees no two active objects on the same level overlap after a step.
- **Stacking (`on_top_of`) stability**: An object with `level = "on_top_of:object_<n>"` is statically stable when the lower object is not a `"sphere"`, `upper.radius <= lower.radius * 1.5`, `upper.weight <= lower.weight * 2.0` (unless `lower.fixed`), and `not (lower.rigidity < 0.2 and upper.weight > lower.weight)`. When the lower object moves, `upper` is carried along if the step displacement is within `max_carry_step(upper, lower)`; otherwise (or if statically unstable) `upper` topples beside the support onto the plane without overlapping.
- **Approximate occlusion (`is_occluded`)**: `is_occluded(viewer_pos, target)` returns `True` when another object has a strictly greater top height (`elevation + height`) than both `target` and the viewer's base elevation, projects strictly between `viewer_pos` and `target` ($0 < t < 1$), and lies within `max(blocker.radius, tolerance)` (default `tolerance = 0.5`) of the line segment.


## T08 — Body verbs: move, look, push, strike, grab, drop, place, speak

- **Verb calling conventions**: Every verb in `src/arden/actions/verbs.py` (`move`, `look`, `push`, `strike`, `grab`, `drop`, `place`, `speak`) accepts `world` either as the first argument (`push(world, target, force)`) or via the active `World` (`push(target, force)`), matching the physics helpers in `arden.world.physics`.
- **`ActionResult` and reason codes**: Verbs validate parameters (`force` and `speed` in `0..1`, `target` or `location` within reach, single held item) without raising exceptions on controller/LLM inputs, returning `ActionResult(ok: bool, reason: str | None, events: list[WorldEvent], data: dict)`. Standard failure reason codes are `"out_of_reach"`, `"too_heavy"`, `"hands_full"`, `"nothing_happened"`, and `"invalid_params"`.
- **Reach and carry thresholds**: Default reach is `DEFAULT_REACH = 1.5` meters (plus `target.radius` for objects) on a reachable elevation/level. Default grab capacity is `MAX_GRAB_WEIGHT = 5.0` scaled by `modifiers.force`; fixed objects or objects heavier than that fail `grab` with `"too_heavy"`.
- **Fragile breaking on `strike`**: Striking an object that matches a `"strike"` `BehaviorRule` with `response="break"` (above `above_force`) or has `fragile=True` above `DEFAULT_FRAGILE_BREAK_THRESHOLD = 0.5` despawns the original object and spawns two non-fragile pieces of half the volume and weight (unless `pieces=0` or `response="remove"` is set, which only removes the object).
- **`BodyModifiers`**: `BodyModifiers(speed=1.0, force=1.0, dexterity=1.0, grab_fail_chance=0.0)` is applied by every verb (passed via `modifiers=...` or read from `world.body_modifiers`). `grab` fails with probability `1 - (1 - grab_fail_chance) * dexterity`, returning `ok=False, reason="nothing_happened"`.
- **`speak` and `SpokeEvent`**: `speak(text)` emits a typed `SpokeEvent` (`type="spoke"`, `source="agent"`, `text=text`, `position=body.position`) on `world.events` and returns it in `ActionResult.events`.
- **Opaque actions (`action_<n>`)**: `register_opaque_action` binds a handler to an `object_<n>` under an `action_<n>` identifier. `available_opaque_actions` offers only actions whose providing objects are currently in reach, and `invoke_opaque_action` fails with `"out_of_reach"` when the object is out of reach.
## T07 — Perception feed: nearby objects, events, body state, affordances, and deltas

These choices fill in configuration defaults, compass bearings, visibility scaling, delta tracking, and text formatting for the perception feed:

- **Perception config (`PerceptionSettings`)**: Added `[perception]` settings to `Settings` (and `arden.example.toml`) with `sensing_radius = 10.0`, `reach_radius = 1.5`, `move_threshold = 0.1`, and `color_visibility_threshold = 0.75`.
- **Compass bearings**: `compass_bearing(from_pos, to_pos)` maps relative 2D offsets to 8-wind compass bearings (`N`, `NE`, `E`, `SE`, `S`, `SW`, `W`, `NW`, with `+y` as `N` and `+x` as `E`) and `"here"` when distance is `0`.
- **Visibility factor and detail filtering**: Effective sensing radius is `sensing_radius * visibility_factor` (`visibility_factor` in `[0.0, 1.0]`, default `1.0`). Occluded objects (`world.is_occluded(body, obj)`) are omitted. When `visibility_factor < 1.0`, fine detail (`color`) is dropped for objects beyond `sensing_radius * (visibility_factor ** 2)` and dropped for all objects when `visibility_factor <= color_visibility_threshold` (`0.75`), while coarse geometry (`shape`, `height`, `volume`, `weight`, `level`, `fixed`) remains until the object leaves the shrunk sensing radius.
- **Affordances within reach**: For perceived objects within `reach_radius` (or currently held), `Percept.affordances` maps `object_<n>` to sorted verb/action tokens. Standard physical verbs derive from object properties and `behavior` rules; non-physical verbs in `behavior` are exposed only as opaque `action_<n>` tokens with all hidden rule parameters and descriptions stripped.
- **Sanitized events and `PerceptionTracker` deltas**: Events in `Percept.events` strip `behavior`, `velocity`, and `source` (`"creator"`). `PerceptionTracker` tracks visible objects across calls, returning a full percept on its first call (or on `full_refresh()` / `perceive(full=True)`) and delta percepts on subsequent calls containing only `appeared`, `disappeared`, `moved` (beyond `move_threshold`), and `changed` objects. When nothing changes, the delta `Percept` has `is_empty = True`, `bool(percept) = False`, and `to_text() == ""`.
- **`look(target)` and `Percept.to_text()`**: `look` returns a `PerceivedObject` with all perceptible properties for a single target object (`look(target)` or `look(world, target)`). `Percept.to_text()` renders a deterministic, token-cheap multi-line format locked by `tests/fixtures/percept_golden.txt`.

## T11 — Ollama / llama.cpp backend with structured JSON output and prompt builder

- **HTTP transport and schema mode (`OpenAICompatLLM`)**: `src/arden/llm/openai_compat.py` uses stdlib `urllib.request` so no extra network dependency is needed. By default it posts to `<base_url>/chat/completions` (or `<base_url>/v1/chat/completions` if `/v1` is omitted) with OpenAI's `response_format = {"type": "json_schema", "json_schema": {"name": ..., "strict": True, "schema": schema}}`. When `schema_mode="ollama"` or `base_url` ends with `/api` or `/api/chat`, it posts to Ollama's native `/api/chat` endpoint with `"format": schema` and `"options": {"temperature": ...}`.
- **Repair retries**: When `parse_json_output` raises `LLMOutputError` (malformed JSON or schema mismatch), `OpenAICompatLLM.complete_json` appends the invalid assistant text and a repair user message containing the validation error detail, retrying up to `max_retries` times (default `2`) before raising the final `LLMOutputError`.
- **Config (`LlmSettings`)**: `[llm]` in `arden.toml` now defines `backend` (default `"mock"`, or `"ollama"` / `"openai_compat"` / `"llama_cpp"`), `base_url` (default `"http://127.0.0.1:11434/v1"`), `model` (default `"qwen2.5:7b-instruct"`), `temperature` (default `0.2`), `timeout_s` (default `30.0`), and `max_retries` (default `2`).
- **Prompt builder (`src/arden/llm/prompts.py`)**: `build_decide_prompt`, `build_reflect_prompt`, and `build_name_prompt` (plus generic `build_prompt`) return a `BuiltPrompt(role, system, user)` (which also unpacks as `(system, user)`). Prompts assemble only numeric `body_state`, `percept_delta`, `previous_intent_result`, `self_model`, and `memories`, without object semantics or evaluative body-state labels (`good`, `bad`, etc.). `estimate_tokens` uses `max(words, ceil(chars / 4))` and truncates `memories` from the tail first when `max_tokens` (default `1024`) is exceeded.
- **`llm-smoke` CLI subcommand**: `python -m arden llm-smoke` builds one `decide` prompt, calls `complete_json` on the configured backend with the `Intent` JSON schema, validates the returned `Intent`, and prints the backend/model, latency in ms, and serialized intent JSON.
## T09 — Building: stack, bind, insert, separate, and composite properties

Section 16 (open question 6) asks how detailed composite physics (`center_of_mass`, `joint_strength`, stability) should be. We choose deterministic, closed-form formulas over constituent `WorldObject` properties:

- **`Composite(WorldObject)` representation and `made_by_agent`**: `Composite` subclasses `WorldObject` so it participates in physics, perception, and save/load like any other object. Every composite (and stacked/inserted structure) sets `made_by_agent = True` (exposed in `state["made_by_agent"] = True` for memory and perception), while internal part trees (`parts`, `binder`, `join_type`, `joint_strength`) are omitted from `perceptible()` and `Percept` events so hidden rules never leak. `World.snapshot()` and `World.restore()` preserve `Composite` instances and their nested parts across ticks and re-joins.
- **Derived physical properties**:
  - `weight` and `volume`: sum of constituent parts plus any consumed `binder` (for `insert`, exterior `volume` and `height` remain those of the hollow container while `weight` includes contents).
  - `height` / `length`: sum of part heights along the joined axis (`Composite.length` aliases `height` or `state["length"]`).
  - `rigidity`: weight-weighted mean of part rigidities (`compute_composite_rigidity`).
  - `shape`: `"long"` when any part is `"long"` or when combined height exceeds `2.2 * max_radius`; otherwise the shared or volume-dominant part shape (`compute_composite_shape`).
  - `center_of_mass` (`CenterOfMass(float)`): normalized axial ratio in `[0, 1]` (`0.5` for a single/balanced object; `> 0.5` when mass is shifted toward the heavier head end, such as a flat stone bound to a light stick) with `.x`/`.y` 2D coordinates (`compute_center_of_mass`).
- **Binding and joint failure under load (`bind(held, target, binder)`)**: Requires `binder.binding == True` and all three objects in reach and non-fixed. The binder and parts are despawned and replaced by a new `Composite`, with `binder` consumed into the joint. `compute_joint_strength(parts, binder)` derives joint strength in `[0.15, 0.95]` from binder rigidity, weight, fragility (`* 0.55` when fragile), and part mass. When a bound composite is used to `strike` (or is struck) with an effective impact force exceeding `joint_strength`, the joint fails (`data["joint_failed"] = True`) and the composite separates back into its non-binder parts.
- **Tool-assisted `strike` scaling**: Striking while holding a tool (or passing `tool=`) scales base force by `strike_impact_multiplier(tool)` (`1.0 + 0.35 * weight + 0.30 * length + 0.20 * rigidity + 0.50 * max(0, center_of_mass - 0.5)`). A stick bound to a heavy stone has greater weight, length, and forward center of mass than the stick alone, producing a stronger impulse and breaking higher-threshold targets.
- **Stacking stability and deterministic toppling (`stack(held, target)`)**: Stacking onto a base object automatically targets the top of any existing stack column on that base. `stack_stability_score(upper, lower, objects)` computes a score in `[0, 1]` from support shape (`flat: 1.0`, `cube: 0.9`, `cylinder: 0.7`, `long: 0.4`, `sphere: 0.0`), radius ratio (`upper.radius <= 1.5 * lower.radius`), weight ratio (`upper.weight <= 2.0 * lower.weight`), rigidity, and cumulative stack depth. Stacks with score `< STACK_STABILITY_THRESHOLD` (`0.50`) topple to the ground at a deterministic angle drawn from `world.rng`.
- **Containment (`insert(held, target)`) and `separate(target)`**: `insert` requires `target.hollow == True` and `held.volume <= target.volume - used_volume`; inserted objects get `level = "inside:<target_id>"`, add their weight to the container, and move with the container across `move`, `push`, `grab`, `drop`, `place`, and physics ticks. `separate(target)` disassembles a `Composite` into its original leaf parts (keeping binders consumed), extracts contents from a hollow container, or unstacks a stacked object onto the ground.
## Issue #35 — Whitelist acceptable state keys

- **Single `state` allowlist (`PERCEPTIBLE_STATE_KEYS`)**: `PERCEPTIBLE_STATE_KEYS` in `src/arden/world/objects.py` is the single allowlist defining which `WorldObject.state` keys `perceptible()` (and perception event sanitization) may return. Every other key in `state` is left out of `perceptible()` while remaining on `WorldObject.state` for internal physics and serialization.
- **`wet` is allowed; `radius` and `floating` are left out**: `PERCEPTIBLE_STATE_KEYS` is `frozenset({"wet"})`. `wet` is included because wetness is a direct physical sensation the agent can feel. `radius` is omitted because it is an internal collision-circle override and the agent already perceives `shape`, `height`, and `volume`. `floating` is left out rather than renamed: `state["floating"]` stays an internal physics flag in `World._step_physics()`, while the agent observes water drift directly from `state["wet"]` and the object's downstream position changes each tick.

## T17 — Day and night cycle: light, visibility, and temperature

- **Day/night config (`DayNightConfig` / `DayNightSettings`)**: Added `[daynight]` settings (`day_length = 600` ticks, `daylight_share = 0.5`, `min_visibility = 0.25`, `temperature_swing = 0.4`, `base_temperature = 1.0`) in `src/arden/environment/daynight.py` and `src/arden/config.py`.
- **Time-of-day fraction and smooth curves**: Time of day is a fraction $t \in [0.0, 1.0)$ with `MIDNIGHT = 0.0`, `DAWN = 0.25`, `NOON = 0.5`, and `DUSK = 0.75`. A new `World` starts at `NOON` (`0.5`) so initial perception has full daylight unless changed. Light follows the smooth curve $\text{raw}(t)^\gamma$ where $\text{raw}(t) = \frac{1}{2}(1 - \cos(2\pi t))$ and $\gamma = \ln(0.5) / \ln(\cos^2(\frac{\pi}{2} \cdot \text{daylight\_share}))$, so the share of the cycle with $\text{light} \ge 0.5$ equals `daylight_share` with no piecewise switches.
- **Visibility factor and ambient temperature**: `visibility_factor` is `min_visibility + (1 - min_visibility) * light`, so the effective sensing radius at midnight equals `min_visibility` times the daytime sensing radius. Ambient temperature is `base_temperature - (1 - light) * temperature_swing`, exposed on `world.ambient_temperature` (and `world.temperature`) for the body-state model (T19).
- **Creator controls and events**: `world.set_time_of_day(fraction)` sets the cycle fraction and emits `TimeOfDayChangedEvent` (`type="time_of_day_changed"`, `source="creator"`). `world.freeze_cycle(bool)` pauses or resumes cycle progression during `world.step()` and emits `CycleFrozenEvent` (`type="cycle_frozen"`, `source="creator"`).
- **Coarse light level in `Percept`**: `Percept.light` (aliased as `Percept.light_level`, rendered in `to_dict()` and `to_text()`) exposes light as a coarse number rounded to 2 decimal places in `[0.0, 1.0]` with no qualitative labels.



## T19 — Body state: energy, comfort, side effects, and drives

- **Config (`BodyConfig` / `BodySettings`) and presets**: `[body]` in `arden.toml` (and `arden.example.toml`) configures energy drain/recovery rates, comfort drain/recovery rates, physical side-effect strengths, and intrinsic drive thresholds, supporting `preset = "default"`, `"gentle"`, and `"harsh"` (`BodyConfig.from_preset`). All speed, force, dexterity, and sensing-radius effect strengths are bounded strictly below `1.0` so nothing ever forces sleep or death, even at `0.0` energy and `0.0` comfort.
- **Energy dynamics**: Energy (`world.body.energy` in `[0.0, 1.0]`) drains passively each tick by `energy_time_drain` (`0.002`) and faster during active verbs via `activity_energy_cost(verb, force=..., speed=...)` (`energy_activity_drain * verb_weight * (0.25 + 0.75 * intensity)`, where heavy verbs like `push` and `strike` have weight `1.0` and light verbs like `look` have weight `0.05`). Energy is restored by resting (`rest(world, ticks)` or `world.step(resting=True)`) and by eating reachable objects that carry an `edible` rule (`eat(world, target)` or invoking an edible object's opaque `action_<n>`).
- **Comfort dynamics**: Comfort (`world.body.comfort` in `[0.0, 1.0]`) is lowered each tick by cold exposure (`world.cold` / low `ambient_temperature`), wetness (`world.wet`, standing on a `"water"` tile, or `"rain"`/`"storm"` weather), night darkness (`1 - light_level`), storms, and low energy (`energy < 0.50`). Comfort is restored by shelter (`compute_shelter_level`: being `inside:` an object, near an agent-built structure or hollow shelter, or explicit `sheltered=True`), dryness, warmth, and rest.
- **Physical side effects (`BodyModifiers`)**: `compute_body_modifiers` maps body state and exposure onto `BodyModifiers(speed, force, dexterity, grab_fail_chance, bind_fail_chance, slip_chance, sensing_radius_scale)` via smooth monotonic curves (`0.5 * u + 0.5 * u^2`):
  - Low energy reduces `speed` and `force` (with `low_energy_effect_threshold = 0.95` on active worlds so fresh full-energy movement stays at `1.0`).
  - Cold increases `grab_fail_chance` and `bind_fail_chance` (and lowers `dexterity`).
  - Wet reduces `speed`, introduces `slip_chance` (causing held items to probabilistically slip and drop during movement or ticks), and compounds with cold to raise `grab_fail_chance`.
  - Very low comfort (`comfort < 0.35`) scales down the effective sensing radius in `perceive()` via `sensing_radius_scale`.
- **Drives (`DriveState`)**: `world.drives` tracks `boredom` (in `[0.0, 1.0]`, rising by `boredom_rise_rate` when `novelty + surprise == 0` and dropping by `boredom_drop_scale * (novelty + surprise)` when novelty or surprise occurs) and `curiosity` (accumulating `curiosity_novelty_weight * novelty + curiosity_surprise_weight * surprise`). Both are exposed to the attention gate via `drives.thresholds()`, `world.gate_triggers()`, and `world.should_wake_gate`, and to episodic memory via `compute_memory_salience` (`world.memory_salience`).
- **Plain numeric percepts**: `BodyPercept`, `Percept.to_text()`, and `format_numeric_body_state()` emit only plain numeric values for `energy` and `comfort` with no evaluative words (`good`, `bad`, `hungry`, `tired`, etc.).
